# VSE Wiki Index

This skill regenerates the two surfaces the wiki derives from page
frontmatter: `wiki/INDEX.md`, the catalogue of every page, and the
`wiki-routing` marker block inside each consuming skill's `SKILL.md`.
It also verifies that every long page carries the contents block the
schema requires.

Nothing here invents content. Every generated cell comes from a page's
own frontmatter, which is what keeps the derived surfaces honest and
makes regeneration safe to run at any time.

**This skill writes to `wiki/INDEX.md` and to the marked region of
consuming skills' `SKILL.md` files.** It never writes to `wiki/pages/`,
never writes to `wiki/LOG.md` (the log is updated by the skill that
invoked this one, typically `vse-wiki-ingest` or `vse-wiki-refactor`),
and never touches a single character outside the
`<!-- wiki-routing:begin -->` and `<!-- wiki-routing:end -->` markers in
a skill body.

Before any action on `wiki/`, read `wiki/CLAUDE.md`. That file is the
binding schema and it defines every format this skill emits.

> Status note for the 3.0.0 release train. Operation B below is
> authored and correct, but the consumer skills do not carry routing
> marker blocks yet. They receive them in the runtime-flip change that
> follows this one. Until then, running this skill regenerates
> `INDEX.md` (operation A) and reports contents-block drift (operation
> C), and operation B finds no marker blocks to rewrite. That is the
> expected result, not a failure.

## When This Skill Triggers

- The contributor invokes `/vse-wiki-index` with no argument (regenerate
  everything) or `/vse-wiki-index <skill>` (regenerate `INDEX.md` plus
  that one skill's routing block).
- Invoked programmatically by `vse-wiki-ingest` after pages are written.
- Invoked programmatically by `vse-wiki-refactor` after refactor changes
  land.

## Step 0: Confirm Contributor Context

Same preconditions as the other wiki skills. Fail fast if not inside the
plugin repo with an initialised wiki:

```bash
test -f .claude-plugin/plugin.json && test -f wiki/CLAUDE.md
```

## Step 1: Enumerate Pages and Parse Frontmatter

```bash
find wiki/pages -type f -name '*.md' | sort
```

For each page, parse the YAML frontmatter and record `slug`, `title`,
`type`, `layer`, `summary`, `confidence`, and `referenced_by`. Record
the page path relative to the wiki root (for example
`pages/sysml2/sysml2-state-machines.md`).

Build two maps from this single pass:

- `layer → [pages]`, each layer's pages sorted by slug. This drives
  operation A.
- `skill → [pages]`, built by walking every page's `referenced_by` list,
  each skill's pages sorted by layer and then by slug within the layer.
  This drives operation B.

Stop and report rather than guessing if a page is missing `summary` or
`referenced_by`. Both are required fields, and generating from a page
that lacks them would produce a table cell the schema cannot justify.
Point the contributor at `/vse-wiki-lint`.

## Step 2 (Operation A): Regenerate `wiki/INDEX.md`

Rewrite the file whole. The format is fixed:

```markdown
<!-- Generated by /vse-wiki-index on <ISO-8601-timestamp>. Do not hand-edit. -->

# VSE Wiki Index

This is the catalogue of every page in the plugin wiki. Skills reach
most pages through their own routing tables. Use this index for
anything a routing table does not name.

- **Read on demand.** Open a page when the task needs it. Never bulk-load
  a layer.
- **Resolving a wikilink.** A `[[slug]]` inside a page body resolves to
  the file `pages/**/<slug>.md` under this directory. Slugs are unique
  across the wiki.
- **Searching.** For a term this index does not surface, run
  `grep -ril "<term>" pages` from the wiki root.

**Total pages:** <n>.  **Total layers:** <n>.  **Referencing skills:** <n>.

## <layer>

| Slug | Title | Type | Summary | Referenced by |
|---|---|---|---|---|
| `<slug>` | <title> | <type> | <summary> | <skill-1>, <skill-2> |
```

Rules for the tables:

1. One H2 section per layer, layers in alphabetical order.
2. Rows sorted by slug within a layer.
3. The Slug cell is the slug in backticks. The Title cell is the
   frontmatter `title` with surrounding quotes removed. The Summary cell
   is the frontmatter `summary` verbatim.
4. The Referenced by cell lists the skills from `referenced_by`, comma
   separated, in the order they appear in the frontmatter. An empty list
   renders as a single hyphen.
5. Escape any pipe character inside a title or summary as `\|` so the
   table does not break.
6. The totals line counts pages on disk, layer directories that hold at
   least one page, and distinct skill names across all `referenced_by`
   lists.

Write the file atomically (temp file, then rename).

## Step 3 (Operation B): Regenerate Routing Marker Blocks

For each skill in the `skill → [pages]` map (or the single skill the
contributor named), open `skills/<skill>/SKILL.md` and replace the text
between the two markers:

```markdown
<!-- wiki-routing:begin -->
| Page | Path | Read when |
|---|---|---|
| <title> | <path-relative-to-wiki-root> | <summary> |
<!-- wiki-routing:end -->
```

Rules:

1. Rows are sorted by layer, then by slug within the layer.
2. The Page cell is the page `title`, the Path cell is the page path
   relative to the wiki root, and the "Read when" cell is the page
   `summary` verbatim. No cell is ever composed or paraphrased here.
3. Escape pipe characters as `\|`.
4. Everything outside the markers, including the preamble paragraph
   above `<!-- wiki-routing:begin -->`, is left untouched. The preamble
   is ordinary skill prose that a skill author may reword.
5. Ignore any marker that sits inside a fenced code block or an inline
   code span. This skill and `vse-wiki-lint` both document the marker
   format, so those occurrences are examples and must never be rewritten
   as if they were live blocks.
6. If a skill named in some page's `referenced_by` has no marker pair in
   its `SKILL.md`, do not invent one and do not edit the file. Report it
   to the contributor as a skill awaiting its routing block.
7. If a skill has a marker pair but no pages point at it, empty the
   block down to the header row and report it. An empty table is honest.
   A stale table is not.

The markers exist so this operation is a surgical replacement rather
than a rewrite. A hand edit inside the markers is a schema violation and
`/vse-wiki-lint` reports it as an error, because the page frontmatter,
not the table, is the source of truth.

## Step 4 (Operation C): Verify Contents Blocks

For each page, apply the schema rule from `wiki/CLAUDE.md`: a page over
100 lines with three or more H2 headings carries a `## Contents` bullet
list of its H2 headings, immediately after the H1.

Report three kinds of drift:

- **Missing**: the page qualifies but carries no `## Contents` block.
- **Stale**: the block exists but its bullets do not match the page's H2
  headings, in document order.
- **Unnecessary**: the block exists on a page that does not qualify.

This operation reports only. It never edits a page. Contents blocks are
page content, and page content is the contributor's, not the
generator's.

## Step 5: Report

Report to the caller (another skill or the contributor):

- Pages indexed, layers covered, and distinct referencing skills.
- Routing blocks regenerated, with the row count for each.
- Skills named in `referenced_by` that carry no marker block yet.
- Skills with a marker block that no page points at.
- Contents-block drift, grouped as missing, stale, and unnecessary.
- Pages with an empty `referenced_by` list. These are reachable through
  `INDEX.md` and through wikilinks, so this is an observation rather
  than a defect.

Do not commit. The caller (or the contributor, if invoked directly)
decides when to stage and commit.

## Determinism

This skill is deterministic. The same set of pages and frontmatter
always produces the same `INDEX.md` body and the same routing blocks.
The generated-file timestamp in the `INDEX.md` header comment is the
only element that varies between runs, and it is confined to that
comment. Running the skill twice with no page change in between must
therefore produce a zero diff apart from that timestamp, and a
non-empty diff means either a page changed or the generator has a bug.

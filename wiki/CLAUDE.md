# Wiki Schema (vse-systems-engineering)

This file is the single source of truth for authoring and maintaining the
VSE knowledge wiki. Every skill, subagent, and command that touches `wiki/`
reads this file first. If there is a conflict between this file and any
other document, this file wins.

The wiki implements Andrej Karpathy's LLM Wiki pattern (April 2026) adapted
for a distributed Claude Code plugin. Atomic markdown pages are authored
from raw sources in `sources/` (gitignored) and stay atomic all the way to
runtime. Nothing is concatenated and nothing is front-loaded.

## The navigable-wiki contract

The runtime surface is the wiki itself. A skill does not receive a
pre-assembled reference document. A skill receives two things:

1. A generated **routing table** in its own body, naming the pages that
   skill is expected to need, with a one-line trigger for each.
2. `wiki/INDEX.md`, the catalogue of every page in the wiki, for anything
   the routing table does not cover.

The skill then reads individual pages **on demand** with the Read tool,
one page at a time, only when the task in front of it calls for that page.
Bulk loading is forbidden. This is progressive disclosure: the routing
table costs a few lines of skill body, and a page costs its own length
only when it is genuinely needed.

Three consequences follow, and they govern everything else in this file.

- **Pages are the only content artefact.** There is no generated content
  file anywhere in `wiki/`. `INDEX.md` and the routing tables carry
  metadata about pages, never page prose.
- **Both derived surfaces come from page frontmatter.** The `summary:`
  field feeds the INDEX summary column and the routing-table "Read when"
  column. The `referenced_by:` field decides which skills carry which
  rows. Regeneration therefore cannot clobber editorial text, because the
  editorial text lives in the page.
- **Navigation must survive one hop.** A routing row points straight at a
  page. It never points at a page that in turn tells the reader to go
  and read a second page before the task can be completed.

## Directory Layout

```text
wiki/
  CLAUDE.md                 This file. Schema and operation contracts.
  INDEX.md                  Generated page catalogue, grouped by layer.
                            Regenerated by /vse-wiki-index. Do not hand-edit.
  LOG.md                    Append-only activity record.
  schema/                   Page-type templates. One file per type.
  pages/                    Atomic concept pages, grouped by VSE source layer.
    ambse/
    hsi/
    incose-vse/
    iso29110/
    methodology/
    needs-and-reqs/
    phas-eai/
    project-structure/
    syside/
    sysml2/
    vv/
```

Never store source files in `wiki/`. Raw PDFs live in the gitignored
`sources/` directory. Scratch markdown produced by `markitdown` during
ingest is temporary and gitignored.

`wiki/LINT_REPORT.md` is written by `/vse-wiki-lint`. It is gitignored and
untracked. It is scratch output for the contributor, never an artefact.

## VSE Source Layers

Pages are grouped by the source-processing order documented in
`CLAUDE.local.md`. This ordering reflects the VSE-first editorial stance:
ISO 29110 is the process backbone, PHAS-EAI supplies design rationale,
INCOSE is scaled for VSE scope, AMBSE governs the agile process, SysML 2.0
is the modelling language, and domain guides cover specific concerns.

| Layer | Directory | Source material |
|---|---|---|
| ISO/IEC 29110 | `pages/iso29110/` | ISO/IEC TR 29110-5-6-2:2014 and successors. |
| PHAS-EAI | `pages/phas-eai/` | kappe.pdf, PHAS-EAI framework papers. |
| INCOSE (VSE-scaled) | `pages/incose-vse/` | INCOSE SE Handbook 4e, filtered for VSE scope. |
| AMBSE | `pages/ambse/` | Douglass 2016 (Agile Systems Engineering), Douglass 2021 (Agile MBSE Cookbook). |
| Methodology | `pages/methodology/` | The plugin's methodology specification at `<plugin>/methodology/`. Atomic-page summaries cross-linked to the spec. |
| SysML 2.0 | `pages/sysml2/` | OMG SysML 2.0 specification and derived notes. |
| Syside tooling | `pages/syside/` | Sensmetry Syside documentation, Python API, and Sysand. |
| Needs and Requirements | `pages/needs-and-reqs/` | INCOSE Guide to Needs and Requirements. |
| Verification and Validation | `pages/vv/` | INCOSE Guide to V&V. |
| Human-Systems Integration | `pages/hsi/` | HSI Primer Vol. 1. |
| Project structure | `pages/project-structure/` | Cross-cutting canonical layout guidance. |

When a new source does not fit an existing layer, do not invent a new layer
without updating this file first. Propose the layer to the contributor and
revise this schema in the same PR that introduces the page.

## Page Frontmatter Contract

Every page under `pages/` carries YAML frontmatter. Missing required fields
cause `/vse-wiki-lint` to fail the page.

```yaml
---
title: "SysML 2.0 Succession Semantics"
slug: sysml2-succession-semantics
type: reference
layer: sysml2
summary: Ordering semantics for successions, including guards and trigger evaluation
tags: [behaviour, execution-semantics]
sources:
  - citation: "OMG (2025). OMG Systems Modeling Language 2.0, §8.4"
    raw: sysmlv2.pdf
related:
  - sysml2-action-definitions
  - sysml2-state-machines
confidence: high
created: 2026-04-16
updated: 2026-04-16
referenced_by: [sysml2-behaviour]
---
```

### Field definitions

- **title** (string, required). Human-readable page title. Sentence case.
- **slug** (string, required). Lowercase kebab-case. Matches the filename
  without the `.md` extension. Unique across the wiki.
- **type** (enum, required). One of `reference`, `concept`, `process`,
  `pattern`, `glossary`. See `schema/` for templates.
- **layer** (enum, required). Matches the directory name under `pages/`.
- **summary** (string, required). One line, under 120 characters, sentence
  case, no trailing full stop. It states what the page covers and when a
  reader would want it. This single field feeds two generated surfaces:
  the Summary column in `INDEX.md` and the "Read when" column in every
  routing table that carries the page. Write it as a trigger, not as a
  restatement of the title. "Ordering semantics for successions, including
  guards and trigger evaluation" is useful. "This page describes
  successions" is not.
- **tags** (list, optional). Short keywords for search. Lowercase, kebab-case.
- **sources** (list, required for non-glossary types). Each entry carries a
  `citation` (bibliographic, readable by end users) and an optional `raw`
  (contributor-only). A page may cite multiple sources. See the raw-path
  policy below.
- **related** (list, optional). List of slugs. Becomes wikilinks in the
  body. See the wikilink section below.
- **confidence** (enum, required). One of `high`, `medium`, `low`. A page
  lowered to `medium` or `low` must state the reason in the body.
- **created** (ISO date, required). Set once, never changed.
- **updated** (ISO date, required). Bumped on every material edit.
- **referenced_by** (list, required, may be empty). Names of the skills
  whose routing tables carry this page. `/vse-wiki-index` generates every
  routing table from this field, so the field is the authority and the
  tables are the derived surface. An empty list is legitimate. It means
  the page is reachable through `INDEX.md` and through wikilinks from
  other pages, but no skill routes to it directly.

### Wikilinks in the body

Cross-references inside the body use Obsidian-style wikilinks:
`[[sysml2-action-definitions]]`. The slug between the brackets matches the
target page's `slug`. `/vse-wiki-lint` resolves every wikilink and fails
on unresolved ones.

Wikilinks are preserved verbatim at runtime. Nothing strips them, because
nothing rewrites page bodies any more. The resolution convention is
therefore part of the runtime contract and is stated in the `INDEX.md`
preamble as well as here:

> A wikilink `[[slug]]` resolves to the file `pages/**/<slug>.md` under
> the wiki root. Slugs are unique across the wiki, so a plain
> `grep -rl "slug: <slug>" pages` or a lookup in `INDEX.md` finds the
> file. Wikilinks are optional onward navigation. A skill is never
> required to follow one to complete the task its routing table
> describes.

### Source citations and raw paths

End users who install the plugin never have access to `sources/`, because
`sources/` is gitignored. Every `sources[].citation` must stand on its own
as a bibliographic reference. Never reference a raw path in the body text
of a page.

`raw:` is contributor metadata that lets `/vse-wiki-refactor` re-open the
original for fact-checking, and that gives `/vse-wiki-lint` the mtime it
needs for the source-freshness rule. The field is **optional per source
entry**. When present it takes exactly one of three forms:

1. An **exact filename under `sources/`**, reproduced character for
   character, including spaces and capitalisation. Quote the value when it
   contains spaces. Example: `raw: "HSI Primer Vol. 1 v4.pdf"`.
2. A **repo-relative path inside the plugin tree**, used by the
   methodology-derived pages. Example: `raw: methodology/01-user-stories.md`.
3. **`null`**, for web-only sources whose `citation` carries the URL. The
   material has no local file, so there is nothing to resolve.

Anything else is a lint error. A value that merely labels the source, such
as a made-up tidy filename that does not exist under `sources/`, belongs in
`citation:` instead, which is the field end users read.

## Routing tables

A routing table is the generated block that tells one skill which pages it
is expected to need. It lives in the skill body, under a `## Knowledge
base` heading, and it is delimited by HTML comment markers so it is both
machine-parseable and safely regenerable.

```markdown
## Knowledge base

The plugin wiki root is `${CLAUDE_SKILL_DIR}/../../wiki`. Read pages on
demand with the Read tool. Do not bulk-load. Pick the pages the task
needs. For anything not listed, consult `INDEX.md` at the wiki root, or
search: `grep -ril "<term>" <wiki-root>/pages`.

<!-- wiki-routing:begin -->
| Page | Path | Read when |
|---|---|---|
| SysML 2.0 State Machines | pages/sysml2/sysml2-state-machines.md | Authoring state def, transitions, entry, do, exit behaviours |
<!-- wiki-routing:end -->
```

Rules:

- **Generation.** `/vse-wiki-index` builds every block from page
  frontmatter. A row exists for skill S and page P exactly when P's
  `referenced_by:` contains S. The Page column is the page `title`, the
  Path column is the page path relative to the wiki root, and the
  "Read when" column is the page `summary` verbatim. Rows are sorted by
  layer, then by slug within the layer.
- **Hand edits are forbidden.** Nothing between `<!-- wiki-routing:begin -->`
  and `<!-- wiki-routing:end -->` may be edited by hand. To change a row,
  edit the page frontmatter and regenerate. `/vse-wiki-lint` compares every
  block against frontmatter and reports any divergence as an error, which
  is what makes a hand edit visible rather than silently authoritative.
- **The preamble is not generated.** The prose above the `begin` marker is
  ordinary skill text. A skill may reword it. Only the marked block is
  owned by the generator.
- **Paths are wiki-root-relative.** The preamble establishes the root, so
  rows stay short. `${CLAUDE_SKILL_DIR}` is substituted at injection time,
  and the preamble also names the root in words so a client that does not
  substitute still leaves the model able to resolve it from the skill
  location.
- **One hop, always.** A routing row must name every page the skill needs
  directly. Chains are forbidden: a row must never point at a page whose
  content is a pointer to a second page the skill must also read.
- **A skill with no pages gets the preamble only**, with no marker block.
  It still needs to know where `INDEX.md` is.
- **Markers inside code are not blocks.** The wiki skills and this file
  document the marker format, so the marker text appears inside fenced
  code blocks and inline code spans. A generator or a linter parsing for
  routing blocks must ignore any marker that sits inside a fenced code
  block or an inline code span, and treat only bare markers in the skill
  body as a real block.

## Operations

Four operations govern the wiki. Each is implemented as a named skill with
a slash-command wrapper.

### ingest

**Skill**: `vse-wiki-ingest`. **Command**: `/vse-wiki-ingest <path>`.

Processes a single new source.

1. Detect the source format. PDF sources are converted to scratch markdown
   via the `markitdown` skill if the `claude-scientific-writer` plugin is
   available. If not, the skill asks the contributor to pre-convert.
2. Propose a layer and a set of atomic pages in dialogue with the
   contributor. Pages should be small (ideally under 200 lines). One page,
   one concept.
3. Dispatch the `vse-wiki-ingestor` subagent to read the scratch markdown
   in isolation and return a suggestion-shaped decomposition proposal.
4. Present the proposal to the contributor for editing.
5. On approval, write pages with full frontmatter (including `summary:`
   and `referenced_by:`), update any related pages' `related:` lists, then
   dispatch `/vse-wiki-index` to regenerate `INDEX.md` and to sync the
   routing marker block of every skill named in any touched page's
   `referenced_by:`. Append to `LOG.md`.
6. Resolve any matching `source-added` stub in `LOG.md` by marking it
   `ingested`.

### lint

**Skill**: `vse-wiki-lint`. **Command**: `/vse-wiki-lint`.

Read-only health check. Writes a report to `wiki/LINT_REPORT.md`
(gitignored scratch) for the contributor to apply by hand.

Checks, grouped by what they protect:

*Frontmatter integrity*

- Every page has all required fields (`title`, `slug`, `type`, `layer`,
  `summary`, `confidence`, `created`, `updated`, `referenced_by`), and
  `sources` on non-glossary types. **ERROR** when missing or malformed.
- `slug` matches the filename, and `layer` matches the parent directory.
  **ERROR** on either mismatch.
- `summary` is one line and under 120 characters. **ERROR** when it
  exceeds the limit or spans lines.

*Routing integrity*

- Bidirectional consistency. For every skill routing block, each row's
  page must list that skill in `referenced_by:`. For every page, each
  skill in `referenced_by:` must carry a row for that page. **ERROR** on
  either direction. A skill named in `referenced_by:` that carries no
  marker block at all is the same error seen from the other side, and it
  is reported as one.
- Path resolution. Every `pages/...` path inside a routing block resolves
  to a file on disk. **ERROR** otherwise.
- Sorted order. Rows within a block are ordered by layer, then slug.
  **WARN** when out of order (the block needs regenerating).
- Summary fidelity. The "Read when" cell equals the page's `summary:`
  verbatim. **ERROR** on divergence, because a divergence means somebody
  hand-edited inside the markers.

*Navigation integrity*

- Every `[[wikilink]]` resolves to a page under `pages/`. **ERROR**
  otherwise. **WARN** when the linked slug is absent from the page's
  `related:` list (stale metadata).
- Orphans. A page with empty `referenced_by:` and no backlink from any
  other page's `related:` list is reported at **INFO**, not WARN. Such a
  page remains discoverable through `INDEX.md`, so an orphan is a
  curation observation rather than a defect.
- Contents blocks. Every page over 100 lines with three or more H2
  headings carries a `## Contents` block immediately after the H1, and
  that block lists exactly the page's H2 headings in document order.
  **WARN** on a missing, extra, or stale block.

*Source integrity*

- `raw:` resolution. When present, the value resolves as an exact filename
  under `sources/`, as a repo-relative path inside the plugin tree, or is
  `null`. **ERROR** on a value that matches none of the three.
- Source freshness. For a `raw:` file that exists, compare its mtime with
  the page's `updated:` date. **INFO** when the file is newer by more than
  14 days (candidate for re-ingestion).

*Editorial integrity*

- Confidence. **WARN** when `confidence: medium` or `low` has no
  "Confidence note:" paragraph in the body.
- Dates. **WARN** when `updated` precedes `created`.
- Tags. **INFO** when `tags` is empty.
- Contradiction candidates. Pages at `confidence: high` that share at
  least two tags and one citation, with definitional paragraphs that may
  conflict. **INFO**, contributor decides.
- Schema drift. A page whose H2 headings do not match its `type` template
  under `wiki/schema/`. **WARN**, because pages may deliberately evolve
  away from a template.

The lint skill never writes to `pages/`, `INDEX.md`, `LOG.md`, or any
skill body. Only `LINT_REPORT.md`.

### refactor

**Skill**: `vse-wiki-refactor`. **Command**: `/vse-wiki-refactor`.

The "occasionally go over everything" operation. Runs periodically (not on
every ingest). Dispatches the `vse-wiki-curator` subagent to walk the full
wiki, re-read raw sources where available, propose merges, splits, new
cross-links, and confidence revisions. Produces a commit plan. The
contributor reviews and the skill applies approved changes.

After the approved changes land, the refactor dispatches `/vse-wiki-index`
to resync `INDEX.md` and every affected routing block, because a merge, a
split, or a retirement changes which pages exist and therefore which rows
are correct.

Typical refactor triggers:

- Several new sources have been ingested since the last refactor and cross-linking has fallen behind.
- A source has been superseded (for example, a new OMG SysML 2.0 revision).
- Lint repeatedly surfaces the same class of gap.
- Scheduled editorial sweep before a release tag on the plugin.

### index

**Skill**: `vse-wiki-index`. **Command**: `/vse-wiki-index [<skill>]`.

Regenerates the derived surfaces. Three operations, all driven from page
frontmatter and all idempotent:

1. **Regenerate `wiki/INDEX.md`.** Walk every page, group by layer, and
   emit one table per layer with the columns Slug, Title, Type, Summary,
   Referenced by. Prefix the file with a generated-file header comment
   naming the skill, a navigation preamble (wikilink resolution, the grep
   pattern, the read-on-demand rule), and a totals line.

   ```markdown
   <!-- Generated by /vse-wiki-index on <ISO-8601-timestamp>. Do not hand-edit. -->
   ```

2. **Regenerate routing marker blocks.** For each skill named in any
   page's `referenced_by:`, rebuild the block between
   `<!-- wiki-routing:begin -->` and `<!-- wiki-routing:end -->` in that
   skill's `SKILL.md`, per the rules in the Routing tables section above.
   Content outside the markers is never touched.
3. **Verify contents blocks.** Check every page against the ToC rule in
   Page sizing below and report drift. This operation reports only. It
   does not edit pages.

`INDEX.md` is committed and ships with the plugin. Routing blocks live
inside the skills that ship with the plugin. Neither is hand-edited.

## LOG.md conventions

`LOG.md` is append-only. Each entry is a level-2 heading with a parseable
prefix:

```markdown
## [2026-04-16] source-added | HSI Primer Vol. 2 v1.pdf
Raw file dropped by the source-added-reminder hook. Awaiting
/vse-wiki-ingest.

## [2026-04-16] ingest | HSI Primer Vol. 2 v1.pdf
Layer: hsi. Pages authored:
- hsi-manning-analysis (new)
- hsi-training-development (new)
- hsi-personnel-capabilities (updated)
Routing resynced: needs-and-requirements. INDEX regenerated.

## [2026-04-16] refactor | editorial sweep
Pages merged: 2. Pages split: 1. New cross-links: 14.
Confidence lowered on: sysml2-quick-ref-connections (medium, reason: OMG
specification §12 clarified connector binding).

## [2026-04-16] index | routing resync
Pages indexed: 130. Routing blocks regenerated: 20. ToC drift: 0.

## [2026-04-16] lint | post-refactor
Orphans: 0. Broken wikilinks: 0. Stale pages: 2 flagged.

## [2026-04-16] restructure | wiki v3 data layer
Schema rewritten for on-demand page reading. Frontmatter migrated.
```

The prefix tags are `source-added`, `ingest`, `refactor`, `lint`, `index`,
and `restructure`. New tags must be added to this schema file before use.

`bundle` is a **historical** tag. It appears in entries written before
3.0.0, when per-skill bundles were the runtime surface. It was retired at
3.0.0 and must not be used in new entries.

## Page sizing

Atomic means one concept per file. A page typically runs 50 to 200 lines.
Pages over 300 lines are candidates for splitting. When a page grows past
300 lines during authoring, stop and propose a split before continuing.

The full reference base spans the layers listed above. `INDEX.md` carries the authoritative page, layer, and routing totals, regenerated on every change.0.0. New material lands
directly under `pages/<layer>/` via `/vse-wiki-ingest`, not in any other
directory.

### Contents blocks

Because pages are now read whole and on demand, a long page needs an
opening map so the reader can judge relevance in the first screen.

The rule is mechanical. A page over 100 lines that has three or more H2
headings carries a `## Contents` bullet list of its H2 headings,
immediately after the H1 and before the orientation paragraph. Shorter
pages and pages with fewer than three H2 sections do not, because a
two-item table of contents adds noise without adding navigation.

```markdown
# SysML 2.0 State Machines

## Contents

- States and state definitions
- Transitions and triggers
- Entry, do, and exit behaviours
```

`/vse-wiki-lint` and `/vse-wiki-index` both check the same rule. Keep the
list in document order and keep it in step with the headings whenever a
page is edited.

## Writing style

UK English throughout. No em-dashes, no semicolons in body text, no
contractions. Plain language first, specialist terms introduced with a
one-line gloss on first use. See `CLAUDE.local.md` for the full style
guide. This file does not duplicate it.
